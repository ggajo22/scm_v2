## 문제 정의

`frontend/src/pages/PurchaseOrders/tabs/UnorderedItemsTab.tsx`의 미발주 현황 화면에 3가지 문제가 있다.

1. **발주처리 액션이 없다.** 담당자가 미발주 품목 1건을 확인하고 실제로 어느 발주처에 얼마에 발주했는지 시스템에 기록할 방법이 없다. 기존 `POST /api/purchase-orders/confirm/`(`ConfirmOrderView`)은 SKU 단위 배치 확정 엔드포인트라 "이 행 하나만" 처리할 수 없고, 여러 주문에 걸친 동일 SKU 전체를 한 번에 묶어버린다 — 이 화면에서 요구하는 "해당 LineItem만" 처리하는 그레인과 다르다.
2. **"자동 추천 발주처" 컬럼이 실무에 쓰이지 않는다.** `DistributorVendorRule` 규칙(처음교육/아가페/성서유니온 3곳)만 매핑하고 나머지 대다수 행은 `-`로 비어 있어, 화면 폭만 차지하고 실제 의사결정에 기여하지 않는다.
3. **보류/제외 품목 뷰에 "타출판사"(`other_publisher`) 건이 섞여 나온다.** SPEC-ORDER-018이 4개 제외 상태(on_hold/order_cancelled/cs_required/other_publisher)를 전부 이 뷰에 노출하도록 설계했으나, 타출판사 건은 원래 Daily Review 업로드가 만드는 것이고 품목 노트 타출판사 탭에서 조회할 수 있는 흐름이 되어야 한다 — 보류/제외 뷰에까지 중복 노출될 필요가 없다. 다만 이 전제에는 두 가지 구멍이 있었다(v1.2.0/v1.3.0에서 순차 발견). 첫째, 미발주 현황의 발주 상태 드롭다운을 통해 담당자가 `other_publisher`를 수동으로 지정하면 노트 없이 상태만 바뀐다(v1.2.0에서 발견 — 아래 R4 REQ-LCONF-304~307이 이 통로를 막는다). 둘째, Daily Review 업로드 자체도 '선택'='타출판사'이면서 메모(레거시 템플릿)/Status(신규 템플릿) 셀이 비어 있으면 `purchase_status`는 기록하되 노트는 만들지 않는다(`purchase_order_views.py:1799`는 무조건, `:1805`의 `if note is not None:`은 조건부 — v1.3.0에서 발견, REQ-LCONF-309가 이 통로도 막는다). 두 통로를 모두 막아야 "보류/제외 뷰에서 감춘 것이 품목 노트 탭에서 대신 보인다"는 전제가 성립한다.

## 확정된 설계 결정

- **D1 (처리 그레인)**: 발주처리는 클릭한 LineItem 1건에만 적용된다. SKU 전체나 여러 행 일괄 처리는 이 SPEC의 범위가 아니다(Exclusions 참조). 기존 `ConfirmOrderView`는 SKU 그레인이라 재사용할 수 없으며, 신규 LineItem 그레인 엔드포인트를 만든다.
- **D2 (확정 발주처 입력)**: 드롭다운(6개 사전 정의 값 — booxen/kyobo/yes24/choeumgoyuk/agape/sungseoyunion) + 자유 텍스트 조합. `warehouse_korea`/`warehouse_ca`/`warehouse_nj`는 드롭다운에서 의도적으로 제외한다 — 창고 선택은 재고 차감을 암시하고, 창고재고 자동 차감은 Daily Review 업로드 경로에서만 발생하도록 이미 확정되어 있다(Exclusions 참조). 목록에 없는 발주처는 자유 텍스트로 입력할 수 있다 — 백엔드는 이미 비어있지 않은 임의의 발주처 문자열을 받는다(`ConfirmOrderView` 선례, `research.md` §1-3).
- **D3 (신규 PurchaseOrder의 status)**: `"confirmed"`로 생성한다 — `UploadDailyReviewView`의 non-warehouse 분기 선례를 따른다(`research.md` §1-4). 담당자가 확정 발주처/단가를 직접 입력하는 행위 자체가 "확정된 응답"이며, `ConfirmOrderView`의 `"pending"`(응답을 기다리는 대기 상태) 의미와 다르다.
- **D4 (타출판사 수동 지정 차단, v1.2.0 — 사용자 승인 2026-08-17)**: 미발주 현황의 발주 상태 드롭다운(`PURCHASE_STATUS_OPTIONS`)에서 `other_publisher`를 제거해 수동 지정 통로를 막는다. `PURCHASE_STATUS_LABELS`에는 남겨 기존 행의 한글 라벨 표시는 유지한다(damaged_exchange 선례와 동일 패턴, `purchaseOrderApi.ts:43-49` 주석 참조). 백엔드는 `LineItemStatusUpdateView`/`LineItemBulkStatusUpdateView`에서 `other_publisher`를 damaged_exchange와 동일한 방식으로 HTTP 400 거부한다(`purchase_order_views.py:2516-2520`/`:2573-2577` 선례). 이로써 `other_publisher`는 Daily Review 업로드 경로로만 생성될 수 있게 된다.
- **D5 (Daily Review 업로드의 노트 무조건 생성, v1.3.0 — 사용자 승인 2026-08-17)**: D4만으로는 불충분하다는 사실이 plan-audit 3차 리뷰(ND-A)로 드러났다 — Daily Review 업로드의 타출판사 분기(`purchase_order_views.py:1780-1817`)는 `purchase_status`를 무조건 기록하지만(`:1799`), `LineItemNote` 생성은 `note`가 `None`이 아닐 때만 실행된다(`:1805` `if note is not None:`). `note`는 메모(레거시 템플릿)/Status(신규 템플릿) 컬럼에서 오며(`excel_utils.py:881-884`), 그 셀이 비어 있으면 `_str_or_none`(`excel_utils.py:760-764`)이 `None`으로 정규화한다 — 즉 '선택'='타출판사'이면서 메모/Status가 공란인 업로드 행은 노트 없이 `other_publisher`만 기록된다. REQ-LCONF-309를 신설해 **타출판사 분기에서만** 메모/Status가 공란이어도 기본 안내 문구로 노트를 생성하도록 한다 — 다른 3개 CS 유형(주문취소/주문보류/CS필요)은 기존 조건부 동작(공란이면 노트 미생성)을 그대로 유지한다(범위를 좁게 유지 — Scope Discipline). `assignee`는 기존 분기와 동일하게 `"CS"`를 유지하고, `note_type`도 `"타출판사"`를 유지해 `LineItemNotesPage.tsx:36`의 `note_type === '타출판사'` 필터가 계속 픽업하게 한다. D4+D5가 함께 적용되어야 REQ-LCONF-303의 "타출판사 노트가 연결된 경우 품목 노트 탭에서 조회 가능" 조건이 **이 SPEC 적용 이후 새로 생성되는 모든 `other_publisher` 행**에 대해 성립한다 — D4만으로는 이 조건이 성립하지 않았다(문제 정의 3번 참조).

## Exclusions (What NOT to Build)

1. **창고재고(WarehouseStock) 자동 차감** — 신규 LineItem 발주처리 엔드포인트는 `WarehouseStock`을 읽거나 쓰지 않는다. 창고재고 자동 차감은 Daily Review 업로드 경로 1곳에서만 발생하도록 이미 확정되어 있다(`project_warehouse_stock_deduction_scope` 메모리 참조). 발주처 드롭다운에서 `warehouse_korea`/`warehouse_ca`/`warehouse_nj`를 의도적으로 제외한 것도 이 경계를 지키기 위해서다.
2. **일괄(bulk) 발주처리** — 이 SPEC은 클릭한 LineItem 1건만 처리한다. 여러 행을 선택해 한 번에 발주처리하는 기능(기존 "일괄 상태 변경"과는 별개)은 범위 밖이다.
3. **`ConfirmOrderView`(SKU 단위 배치 확정, `POST /api/purchase-orders/confirm/`)와 `UploadDailyReviewView`(Daily Review 업로드) 로직 변경** — 두 기존 엔드포인트는 원칙적으로 이 SPEC에서 무변경이며, 신규 엔드포인트는 완전히 별도의 코드 경로다. **단, REQ-LCONF-309(v1.3.0)가 규정하는 좁은 예외 하나가 있다** — `UploadDailyReviewView`의 CS 분기 중 `note_type == "타출판사"`인 경우에 한해, 메모/Status 셀이 비어 있을 때의 노트 생성 여부만 변경한다. 그 분기의 나머지 로직(`purchase_status` 기록, `confirmed_distributor`/`confirmed_price` 해석, 다른 3개 CS 유형의 조건부 노트 동작)과 `ConfirmOrderView` 전체는 이 예외에 포함되지 않으며 무변경이다.
4. **`DistributorVendorRule` 규칙 자체(발주처 규칙 설정 탭, 처음교육/아가페/성서유니온 매핑)의 CRUD 로직 변경** — 미발주 화면의 소비 방식(자동 추천 컬럼)만 제거하고, 규칙 데이터·관리 화면·Daily Review에서의 활용은 그대로 둔다.
5. **`on_hold`/`order_cancelled`/`cs_required` 3개 제외 상태의 노출 범위 변경** — 이 SPEC은 `other_publisher`만 보류/제외 품목 뷰에서 제거하며, 나머지 3개 상태는 SPEC-ORDER-018이 정의한 그대로 유지한다.
